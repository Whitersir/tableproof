# 一条任务是怎样完成的

## 先理解不用 AI 的流程

```text
你在浏览器选择两张 CSV
    ↓ POST /api/datasets
tables.parse_csv：检查编码、表头、列数，所有单元格保持字符串
    ↓
storage：保存原始副本与解析结果，返回数据集编号
    ↓ 你选择字段，点击“开始本地核对”
POST /api/runs/local
    ↓
reconcile：筛选 → 按标识分桶 → 排除空标识和冲突 → 精确匹配 → 统计
    ↓
SQLite 保存结果与执行记录，接口返回页面预览
    ↓
JavaScript 使用 textContent、createElement 更新页面
    ↓ 点击下载
reports：读取全部结果，生成报告/CSV
```

`dataset_id` 像文件夹的编号，表示这次导入了哪两张表；`run_id` 像一次实验的编号，同一数据集可以用不同规则核对多次。

Python 字典 `values` 保存原始字段，`record` 保存 CSV 记录号。身份键是元组：按学号时是 `('001',)`；按姓名+班级时是 `('林一', '软工一班')`。元组可以作为字典键，因此能把相同标识的记录聚合在一起。

请注意：模型不参与 `reconcile()` 的数值计算。即使完全不配 API，数据核对和下载仍然是真实运行的。

## 加入模型后，变化在哪里

```text
你输入任务
    ↓ POST /api/runs/agent（返回任务编号，浏览器定时查询状态）
agent.run_agent：把目标与工具说明发给模型
    ↓
模型返回工具名 + JSON 参数
    ↓
本程序检查工具名是否在允许列表、参数是否合法
    ↓
执行普通 Python 函数，把结构化结果作为 tool 消息回传
    ↓
模型决定下一步：提交方案审阅 / 再调用工具 / ask_user 暂停 / 结束
    ↓
最终报告仍由 reports 模块根据核对结果生成
```

模型可以选择四个工具：

| 工具 | 输入 | 返回或改变什么 |
|---|---|---|
| inspect_tables | 空对象 | 文件名、字段、记录数 |
| reconcile_attendance | 两表匹配字段、分组字段、精确筛选 | 首次提交方案等待审阅；确认后同参数执行，本地保存完整结果，向模型返回统计摘要 |
| summarize_by_group | 报名表的分组字段 | 使用原匹配和筛选口径重新分组 |
| ask_user | 问题文字 | 状态变为 needs_input，等待你的回复 |

这不是让模型自由操作电脑。它只能调用我们提供的函数；未知工具被拒绝，参数会由 Pydantic 校验。模型不能自己勾选“仅用姓名匹配”的确认。

## 一段具体的数据流

1. 用户说“按学号核对，按班级统计”。
2. 模型调用 `inspect_tables`，发现报名表字段叫“学号”，签到表叫“学生编号”。
3. 模型调用 `reconcile_attendance`，传入 `registration_keys=['学号']`、`checkin_keys=['学生编号']`、`group_by='班级'`。
4. 参数通过规则检查后，任务变为 needs_review；页面展示方案，此时没有执行核对计算。
5. 用户确认后，后台将确认信息续接到对话，模型以相同参数再调用核对工具。
6. Python 得到有效报名 6、到场 4、未到场 2，摘要回传模型。
7. 模型结束，程序报告展示 66.67%。原始人员明细仍在本地。

以上是预期过程与模拟测试覆盖的流程；真实模型是否正确完成，要接入你的中转站后验证。

## 页面上的模型设置

settings.py 负责本机配置、密钥复用规则和连接探测；model_client.py 负责实际请求。进程环境变量优先于页面保存，页面保存优先于项目 .env。

设置查询只返回 has_api_key，不回传密钥。留空可保留同一接口的已有密钥；更换地址必须重新填写，避免旧密钥被误发给其他服务。连接探测要求显式勾选，发送的是工具格式测试，不包含表格。

## 为什么有两种核对方式

本地方式是可靠的基础和对照组，规则由你明确选择。Agent 方式让模型将自然语言要求映射为工具操作，但也增加理解错误、接口失败和成本。

固定任务用本地核对就够了。我们要通过评测确认，Agent 是否在不同任务中减少手工操作，同时没有改变统计口径。

## 失败怎么观察

- CSV 格式问题：上传时显示具体原因，不创建可用数据集。
- 字段或参数错误：工具返回可处理的错误，模型可以调整或追问。
- 同名风险：暂停并要求确认；重复姓名不靠确认直接消除歧义。
- 接口失败：保存 failed 状态，展示 HTTP 类别或超时提示，不回显服务商响应正文与密钥。
- 内部异常：终端只记录任务编号、异常类型与函数位置，不输出请求头；页面保留失败状态。
- 轮数到限：停止任务，不无限请求。

SQLite 中的 `messages` 保存续接所需对话，不通过普通任务接口返回；`trace` 是给你看的操作记录。它记录动作和结果状态，不等于完整的模型思维解释。
