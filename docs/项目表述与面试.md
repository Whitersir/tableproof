# 项目事实、个人贡献与面试准备

## 当前事实

项目实现了 CSV 上传、字段配置、报名签到核对、异常记录、分组统计、报告导出、SQLite 历史与任务状态。Agent 包含工具参数校验、执行循环、方案审阅与修改、追问续接、轮数限制与接口错误处理。用户可通过网页配置自己的 API，并显式测试工具调用兼容性。

**当前主要工程代码由 AI 辅助生成和调试；用户本人具体参与、理解程度和独立修改能力尚未确认。真实中转站模型还未联调。**

因此，下面是项目客观介绍，不应直接改写为“我独立设计并实现全部系统”。

> 表有据 TableProof 是一个使用 Python、FastAPI、SQLite 与原生 JavaScript 实现的本地表格核对工具，支持报名签到精确匹配、重复与冲突检查、来源追溯及报告导出；另实现可配置的模型工具调用循环，通过模拟接口验证追问续接与失败处理，真实中转站模型接入待验证。

## 面试练习

1. 为什么要把数字计算放在 Python，而不是让模型直接读表回答？
2. 什么情况下普通程序就够了？Agent 比本地表单多承担了什么职责？
3. `001` 为什么不能转成整数？空学号为什么不能匹配到一起？
4. 重复报名与标识冲突有什么区别？冲突为什么排除出分母？
5. 两个人同名时，仅凭用户勾选确认能否解决身份问题？
6. 模型返回工具调用后，究竟是谁执行函数？下一轮怎么拿到结果？
7. 工具名不在允许列表、参数错误、接口超时分别如何处理？
8. 为什么需要轮数上限和显式重试？失败任务保留了哪些信息？
9. 一个表格统计结果完全正确，为什么仍可能没有完成用户任务？
10. 模拟测试、真实模型评测和真实用户试用各自证明了什么？
11. 网页为什么用 `textContent` 展示表格值？下载 CSV 为什么处理公式前缀？
12. 如果数据量和用户数增加，当前 SQLite、后台线程和本地文件方案的限制是什么？
13. 合法参数为什么还需要用户审阅？如何避免未确认就执行核对？
14. 更换模型地址时，为什么不能直接复用旧站密钥？
15. 接口能返回普通文字，为什么还不代表支持工具调用？

第一轮先练习 1—5 题，能结合代码说明即可；不用一次背完所有答案。
